# 2.2.0 · 渠道附件与合并接收

正式版，已验证宿主 **DSH 0.1.5-rc.1**；要求 Node.js **^22.19.0 或 >=24.0.0**。保留旧宿主兼容分支，未重新完成全部旧宿主端到端验证。

## 更新

- Matrix / Mattermost 私聊支持图片、文件、音频和视频收发；收到的附件先保存到当前会话 `inbound/`，再提供文件路径和用户文字。支持的图片通过宿主附件接口交给模型。
- Mattermost 保留带附件消息中的文字；Matrix 支持图片、文件、音频、视频事件及标准 caption。
- 修复客户端拆开发送文字和附件时，文字先执行、附件延迟到下一轮的问题。约 1 秒收集窗口内获取后续事件，合并同一联系人、同一房间中时间跨度不超过 2 秒的相邻附件消息；纯文字消息保持独立。
- 合并输入等待全部附件下载完成，路径显示在用户文字前；下载失败不只执行文字。整组原始事件统一记回执，收集阶段不提前提交游标。
- 显式附件工具按当前消息来源选择渠道，不再误选共享会话中的本地路由。交付记录固定原始渠道，重试不能跨渠道；旧版未保存目标的记录需用原文件 path 重新提交。
- 下载只使用已配置服务器的认证接口，不访问消息中的任意 HTTP 地址，不跟随重定向；Mattermost 校验文件与原始消息归属，上传后再次验证身份再发送。

## 限制

- 入站单组最多 8 个附件、合计 64 MB；出站单个附件最多 64 MB，服务器可能另有更小限制。
- 音视频作为文件接收和交付，不自动转写或理解。Matrix 加密房间/附件、群聊、Mattermost 线程仍不支持。
- 缺少客户端关联信息时，超过收集窗口才到达的附件无法保证与文字合并；不无限等待上传，以免阻塞普通消息。
- 原生 `present` 仅展示于 DSH，不自动投递渠道；渠道交付需使用 `partner_send_attachment`。本版不包含此前诊断的首步伙伴工具注入时序修复。

## 验证

463 项自动化测试通过，覆盖认证收发、上传确认、大小限制、重定向拒绝、授权撤回、跨轮询合并、下载失败不执行和路由隔离。已在本地部署核对 Matrix 图片与文字合并进入同一条会话输入。Mattermost 媒体收发通过模拟服务器验证，未向真实联系人发送测试附件。

存储迁移规则与 2.0.0 一致，不会因安装自动迁移。详见 [渠道说明](../direct-channels.md)。
