# 2.27.11

- 统一角色聊天运行策略：在载入和配置提交时解析并缓存，工具目录、提示词和执行规则使用同一结果。关闭角色聊天后，人物语气、关系、短句分段、睡眠、主动活动和强制后台等规则不再限制普通伙伴；保存的设置保留，重新开启后恢复。
- 角色聊天的长任务交给原生后台，完成后交前台表达和分段投递；后台只接收任务所需信息与来源权限。成果投递优先于普通接话，附件按实际需要提供，不强制生成报告。
- 移除连续执行中的固定 700 token 输出限制；日常直接回复优先一句自然短句，内容多再分段，可单独回复表情包。任务结果不再被摘要长度截断。
- 完善角色后台工作会话回收、目录清理与取消后继续流程，保留运行和待交付任务，避免重复目录名导致历史加载失败。普通伙伴的原生子会话不受角色自动清理规则接管。
- 改善本地群聊识别：结合当前角色、实际已发送对话与场景证据判断呼唤、续接、吐槽和分享，减少已被识别的呼唤仍被旁听过滤；本地请求共用时限，超时不重复推理。
- 在宿主冻结本轮工具集合前准备工具，避免恢复会话首轮出现 unknown tool；权限与渠道撤权仍在统一执行入口核验。
- 修复关注执行把宿主技能目录误当成新用户消息，导致“未返回最终答复”和错误恢复判断的问题。最终答复认领与恢复判断共用上下文分类；真正用户、新任务和未知输入仍保持打断边界。记录受阻答复不代表产物生成成功。
- 关注任务遇到明确宿主中断时，按持久化退避进行有限恢复，先核对原有成果和外部回执；授权变化、取消和新输入不自动重放操作。

## 安装与迁移

通过 npm 升级 `@lemoncat7/dsh-partner@2.27.11` 后重启对应 Profile。无需迁移存储；关闭角色聊天不会删除人物设置或历史。

原生目录清理、取消后重挂执行以及冻结工具前的准备事件，涉及特定宿主实现。本次 npm 包不会自动修改宿主；部署脚本、适用边界与验证方法见 [宿主兼容补丁](../../ops/host/README.md)。已有原生支持时应优先使用原生实现；未知实现不盲目套补丁。群聊本地识别服务需要同步更新仓库中的 `ops/attention` 配置和模型文件。
