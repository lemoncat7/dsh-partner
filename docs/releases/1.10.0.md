# v1.10.0 · 需求看板与统一交付

正式版，适配 DeepSeek Harness **0.1.2-rc.1**；Node.js `^22.19.0 || >=24.0.0`。npm 使用 `latest` 标签。知识库挂载管理需要 `dsh-knowledge 2.4.0+`；异步回写建议搭配 `2.6.0+`。

## 需求到交付

- 每个新任务归属一个需求；通过 `partner_requirements` 创建、提交规划、调整范围及收尾，`partner_task_board` 管理子任务执行和验收。
- 所有子任务安排好后提交规划，全部子任务验收通过后统一总结并归档。子任务执行、核验和完成不逐项通知渠道，最终结果只回到需求来源渠道。
- 支持人工汇总、修改收尾负责人、失败自动重试和手动重试。已保存的总结不会因为渠道投递失败而重新生成。
- 内置任务规划 Skill `1.4.0` 明确需求关联与专业分工，伙伴技能使用 `partner_skill` 加载，不错误调用原生 `skill`；不增加强制前置技能或路由门禁。

## 看板与弹窗

- 首页使用需求卡片，区分进行中、已归档与未归类旧任务；进入需求再查看阶段和子任务，空阶段不占位置。
- 统一新建和详情弹窗；结果优先，交付记录、活动和管理操作按需展开。保留现有配色、字体及材质，不添加常驻卡片动画或额外模糊层。
- 手机、平板横屏与桌面适配；列表分批展开，隐藏页面暂停轮询，旧响应不能覆盖新操作结果。

## 稳定性与升级边界

- 重复删除成功处理；关联执行收到取消信号，迟到结果不重建已删除任务。未完成的依赖者暂停，需求重新确认范围后再提交。
- 归档保存已验收交付快照，删除子任务不抹去最终结论；旧任务不自动合并、不清空。兼容未指定需求 ID 的旧调用时创建单任务需求。
- 汇总与投递使用持久化状态和重试退避。已确认发送按 receipt 去重；网络发送与本地写入不是跨系统事务，不承诺绝对 exactly-once。
- 渠道只提取本轮最终答复，文件引用解析为真实附件；挂卡未读数字位于卡片上方。
- 不修改 DSH 核心、不扩大伙伴管理权限。

## 验证

220 项自动化测试通过；60 个任务的手机、横屏、桌面及深浅色六组浏览器验证通过，覆盖归档、表单、详情、阶段展开和提交模式。
