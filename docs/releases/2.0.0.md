# 2.0.0 · 规范存储与安全迁移

伙伴插件正式大版本。已验证宿主：**DSH 0.1.5-rc.1**；要求 Node.js **^22.19.0 或 >=24.0.0**。
保留旧宿主兼容分支，未重新完成全部旧宿主端到端验证。

## 主要变化

- 左栏按「功能 / 设置」分组；功能包括 Skill 市场、任务看板、定时任务，设置包括基本设置和卡片设置。
- 私有配置、渠道与配对、会话关联、记忆、关注、计划、执行和通知交付数据统一进入 `partners/<id>/.partner/`。
- 公共状态、Skill 与索引进入 `dirname(statePath)/storage-v1/`；不可变私有快照由公共清单原子引用。
- 独立 `storageVersion` 与逐版本迁移注册器；缺失为 0，本版目标为 1，不与插件版本混用。
- 启动仅检测版本，通过卡片消息提示，点击直达升级迁移；同版本去重，不发送到外部渠道。

## 升级步骤与安全边界

1. 备份现有数据并结束伙伴执行，打开「设置 → 基本设置 → 升级迁移」。
2. 检查目录并确认。暂停读写，完整备份登记的数据，复制到暂存目录，校验哈希与 SQLite 完整性。
3. 校验通过后提交存储版本，再核对备份并清理旧路径。源变化、文件占用或备份校验失败时保留原文件，可单独重试清理。

历史 `memory-backup-*`、`memory_backup`、`memory_back` 等按原名称归档，不合并进活动记忆。
完整备份保存在 `migration-backups/<事务 ID>/`，不自动删除。用户工作文件、宿主凭据、会话与知识库不搬动。
迁移请求立即返回 202；页面在重载的 404/502/503/504 期间自动查询恢复，有超时上限，绝不自动重复提交写操作。

**安装本版不会自动迁移；完成迁移后，不能直接降级为不支持新布局的插件。**
不要手工改版本、并行运行旧插件或在迁移期间外部编辑数据。回滚前先保存迁移后的新增数据。

## 验证

429 项自动化测试通过，覆盖拆分读写、数据库与投递记录、失败恢复、完整备份、旧路径清理及 API 状态查询。
浏览器检查覆盖移动端/桌面、浅深色、确认/取消及连续 504/404 后恢复。
当前部署数据核验：11 位伙伴配置记录完整，22 个记忆/关注数据库完整性和表记录数一致；28 项旧源完成清理，两个历史记忆备份归档内容一致。
这是当前环境验证结果，不表示所有部署环境和旧宿主版本均已测试。

详细布局及恢复限制见 [存储迁移说明](../storage-migration.md)。
