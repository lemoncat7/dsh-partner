# 2.7.4 · 微信扫码可靠性与伙伴删除流程

适配 **DSH 0.2.0-rc.2**，Node.js **^22.19.0 或 >=24.0.0**；未修改 DSH 核心源码。

- 微信扫码查询改为串行，服务端合并重复请求；扫码确认与渠道保存支持幂等重试，避免成功后误报会话已过期或重复创建渠道。
- 临时网络超时不再直接终止扫码。凭据保存失败保留确认状态供重试，重复绑定其他伙伴的机器人会给出明确提示。
- 新增「重新扫码」，位于微信启用开关右侧；重新登录保留原渠道标识和联系人授权，不允许把授权转给其他机器人。
- 补充首次长轮询和私聊审批说明：扫码完成机器人登录；收到首条联系人消息后才出现审批，连接成功本身不依赖非空消息。
- 将「删除伙伴」从身份页面移到总览，复用统一确认弹窗，显示关联渠道数量；确认后自动停止渠道并清理登录凭据、联系人绑定及伙伴专属数据，无需先逐一解绑。
- 保留最后一个伙伴、运行中任务和共享/异常目录的保护；DSH 原会话日志仍由宿主管理。

本地构建已在正式容器部署验证；新伙伴扫码、重复确认、保存重试、渠道清理及目录保护有自动化回归覆盖。真实微信服务与网络异常仍以现场复现为准。
