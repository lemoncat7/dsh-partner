# 2.5.0 · 长任务续接与看板等待协调

正式版。已验证 DSH **0.1.5-rc.1**，Node.js **^22.19.0 或 >=24.0.0**；保留已有 DSH 0.1.2-rc.1 兼容声明，该旧宿主不作为本次部署验证基线。

- 新增 `partner_schedule defer/resolve/cancel` 一次性长任务续接：保存外部任务身份、截止时间、次数预算及轮次 token，重启后核验已有任务，不重新提交外部工作。
- 看板续接支持 `boardTaskId`，按实际执行会话自动匹配唯一委派。等待释放执行位、保留独占资源，不反复派发、不提前送验收、不发送中间渠道通知。
- 定时检查只核验外部状态，pending 延期原预约，completed 由看板恢复原任务并继续后续步骤；不会两边同时执行 nextStep。
- 修改需求、改派或删除任务使旧预约失效；取消、删除预约或撤权安全阻塞等待任务，不自动重提交。普通独立预约保持原有行为。
- 恢复会话在模型请求装配前准备身份与工具，避免首次唤醒时工具缺失；缺少核验工具时明确记录受阻。
- 增加可选的“长任务等待与续接”内置技能和预约状态展示，不自动开启能力或扩大工具权限。
- 旧的一次性预约可在原会话、相同外部 ID 与 taskKey 下重新关联当前任务；不猜测迁移或删除旧周期计划，不自动取消外部服务任务。

验证：全量 573 项自动化测试通过，最终构建和 26 项续接定向测试通过。详见 [续接协议与恢复边界](../long-task-continuation.md)。
