# 2.9.1 — 人格表达与试聊一致性

开启人格强化后，普通会话以当前角色参与交流；明确提出工作任务时继续遵守工具授权、事实和交付要求。旧身份、历史回复、记忆摘要和参考示例不能覆盖当前人格卡的表达风格。通过具体反应体现性格，减少解释自己在扮演什么性格、机械服务邀请和无依据的情绪推断。

试聊复用正式会话的身份提示，并将历史按 user / assistant 消息顺序发送，不再把整个对话包装成一条 JSON 用户消息。它仍是隔离试聊：不调用工具、不读写正式记忆、不发渠道消息；不能据此声称已验证完整生产会话的所有行为。

未启用人格卡的身份保持原行为。工作、心跳和结构化输出仍遵循原协议。通用向导示例与既有配置内容不会被迁移改写。没有新增润色模型调用，不增加额外生成轮次。

验证包括试聊消息角色、历史上限、隔离约束、模型选择、失败恢复、旧身份与工作场景兼容，以及已有会话与记忆回归。`ops/evaluate-character.mjs` 提供八个隔离模型试聊场景，输出仅供人工评审，不以关键词检测冒充人格质量评分。

部署脚本保留旧包与安装元数据，并在停写期间备份公共状态以及伙伴工作区中的 `.partner` 私有状态。生产验证要求插件 API 可用，不能仅凭容器健康状态判定完成。
