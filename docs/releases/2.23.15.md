# 2.23.15

修复开启滚动窗口后，自主活动仍不断积累并触发宿主摘要压缩的问题。旧逻辑只把真实用户消息计为对话轮次，少量用户消息之后的连续自主活动无法被字符预算正确裁剪；有效上下文中没有用户消息时更会直接跳过轮次裁剪。

现在，伙伴自己发起的自主活动同样按完整会话轮次参与窗口轮数与字符预算。当前尚未结束的活动、未完成的工具调用及配对结果仍保留；系统上下文和其他来源的保护快照沿用原有规则，不把任意插件通知视作自主活动。设置说明同步标注这一计数方式。请求组装阶段也执行滚动，使宿主进入 pre-step 压力检查前已移出旧轮次，避免压缩插件监听顺序抢先处理旧上下文。

只调整有效上下文的滚动范围，原始历史、回忆检索、人格、关系、模型设置均不改写。没有关闭宿主的溢出保护：单个当前任务过大或受保护上下文本身超过容量时，仍可能需要宿主处理，不能通过丢弃当前工具链来强行避免压缩。
