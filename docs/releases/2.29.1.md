# 2.29.1

- 区分原生后台 Jobs 与子 agent：单条长命令、下载、转码、构建或测试可直接后台运行；独立分析、创作和连续多步工作再委派子 agent。原生 Jobs 运行时，伙伴仍显示忙碌。
- 子 agent 工作改用宿主原生创建、续接和停止接口，自动进入原生任务目录。相同来源、相同 B 站视频的进行中下载会复用原任务，减少因标题改写而重复执行。
- 原生 Job 完成后按原发起人和渠道交付；共享会话中，不将旧任务的完成通知混入其他用户的新问题。渠道或授权变化时不转投新对象。
- 模型生成的工具参数因 JSON 语法错误而未执行时，在当前请求内最多自动重试两次；保留已经成功的工具回执，不重新执行已创建的任务、命令或发送。
- 自主活动按主动交流场景处理，不再将系统提示或已回答的旧问题当作用户新发言。QQ 群聊记录旁听、跳过与已回复状态，减少在后续触发时补答旧内容。
- QQ 群中的纯图片分享可交给会话模型理解，再决定接话或保持安静；失效的历史附件不反复补载。
- B 站视频详情兼容 `video_info` 调用名，并分别提示操作不存在、能力未开启、未登录和当前会话权限限制，避免将接口名称错误误报为需要重新登录。
- 按同一次聊天工具调用归属消除终结回复的重复展示；记忆、时间线和各配置弹窗统一为伙伴界面的半透明材质。
- 渠道通用 TTS 和浏览器设置随主界面加载，打开设置不再依赖旧版本的延迟分块。增加分块返回 404 时仍能打开两种设置的真实浏览器回归检查。
- 启动时的旧对话记忆补录改为显式开启；记忆 worker 空闲时逐步放缓。疲惫值在状态变化时保存，周期调度认领和关闭收尾进一步减少重复写入与重复派发。

升级保留既有配置、对话、记忆和文件。旧格式后台任务首次继续时，基于原历史建立原生子会话；业务 taskId、工作目录与已有产物保留。

执行与维护细节见[后台读写与任务生命周期](../runtime-maintenance.md)。发布验证包括完整回归、配置弹窗与通用设置的浏览器检查，以及实际 npm 压缩包的资源与加载检查。
