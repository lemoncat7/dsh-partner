## 启动问题与修复

第一次启动遇到宿主遗留的 `.credentials.yaml.lock`（原 PID 7）。容器 PID 复用让宿主误判旧锁仍有持有者，连接插件未激活。确认该数据卷只有一个运行容器后停止服务，备份并删除失效锁，再启动恢复。凭据内容未修改。

部署脚本已增加单写入容器校验、停机状态下的失效锁备份处理，以及真实伙伴 API 就绪检查，避免只凭容器健康检查判断成功。
