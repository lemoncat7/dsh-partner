# Matrix / Mattermost 回复进度

普通已授权文本会话处理时续期原生输入提示；超过约 1.5 秒才创建进度消息，快速回复直接发送最终结果。

Matrix 同一处理分段在「等待处理」「处理中」「工具执行中」「整理回复」之间更新；阶段变化最多约每 8 秒写一次，仅发送固定阶段。Mattermost 按下述规则分块展示工具名称与状态。两者均不发送工具参数、原始结果、凭据或模型思考。

成功插入补充消息后，旧进度标记为「下方继续」，不再接收工具状态或最终回复；新进度在补充消息之后创建。任务本身持续执行，不重新调用 Agent。晚到的消息 ID 与收尾操作串行处理，避免重新编辑旧消息。不同渠道、房间和联系人各自隔离。

- Matrix：`typing` API 和 `m.replace` 编辑事件；结束时用最终富文本替换当前分段的进度消息，长回复另发后续分段，显式关闭输入提示。
- Mattermost：采用分块投递，不依赖服务端 Agents 插件。工具调用前已完成的正文说明单独发送；连续工具调用聚合到当前 `props.attachments` 卡片，显示工具名、完成/失败/执行中及耗时。下一段正文或插入消息会封存旧工具块，不再回写旧块。最终 Markdown 回复单独发送。没有确认结果的工具只显示「未确认完成」，不推断成功。
- Mattermost 过程块约每 4 秒批量刷新，分段边界立即收尾；每块最多 32 个工具，超过后换块。待投递操作最多 64 项，过程投递异常或积压超限后关闭本轮中间反馈，最终回复仍独立发送。不会因网络超时重复创建过程消息。
- 此版发送的是工具调用前的已组装正文，不是逐 token 正文流；不外发 reasoning、工具参数、原始结果或内部看板执行通知。工具名仅允许有限长度的标识符，其他名称统一显示为「工具」。
- 进度创建失败不重复 POST，不阻塞伙伴执行。明确不支持编辑时尝试另发最终结果；不确定的网络失败不盲目重发，以减少重复回复。
- 中断时尽力改为失败提示，撤销授权后不继续发文字。进度是临时状态，进程突然退出可能留下未收尾的提示；没有新增自动恢复或重跑工具任务。

## 职责边界

- `execution/reply-progress.ts`：把执行事件映射为固定阶段或白名单工具状态/正文说明，不了解渠道协议。
- `channels/reply-progress-controller.ts`：单次消息生命周期、延迟、节流、串行收尾和错误降级，不解析执行事件。
- `channels/reply-blocks.ts`：正文/工具块的顺序、工具状态聚合和有界投递，不了解 Matrix/Mattermost 协议。
- `channels/direct/progress-transport.ts`：Matrix / Mattermost 协议映射、房间身份校验和消息格式，不管理 Agent。
- `agent-runtime.ts`：仅在该次回复执行期间订阅事件，完成后释放订阅。
- `channels/manager.ts`：关联来源渠道、检查授权并协调上述组件。通知群发设置不改变进度消息的目标。
