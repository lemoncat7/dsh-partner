# 通知渠道与接收人

在伙伴「渠道 → 通知与交付 → 配置」中选择：

- 最近联系的渠道与用户：按最后收到消息的时间选择，不按后台会话活动选择。
- 指定渠道与接收人：多选渠道，再选择每个渠道的已授权接收人。同一通知分别投递。

仅影响主动通知、关注提醒与结果交付。普通聊天回复、交互式审批和明确向当前会话发送的附件仍使用来源渠道。

旧版联系人上的投递规则在首次保存新设置前继续生效。保存后由伙伴级配置统一接管，修改身份不会丢失配置。目标必须属于同一伙伴；撤销授权或停用渠道后不能继续发送，也不自动换人。

## 重试语义

每条逻辑通知保存接收人快照、待发送正文及附件描述、已确认发送的部分。各目标独立发送，一个目标失败不会阻止其他目标。调用方重试相同通知时，跳过已确认成功的部分；关注使用观察记录 ID 作为稳定标识，重启后仍可恢复。

配置变更只作用于新通知；待重试通知保持原接收人。完成后清除账本中的正文与附件描述。账本上限 1000 条，仅淘汰已完成记录，不静默淘汰待处理进度。历史完成回执不是无限期保留。

重试由原有关注/任务处理流程触发，此改动不引入独立的无限重试后台任务。远端已接受但网络丢失确认时，无法保证绝对不重复；只能跳过本地已确认的成功发送。

## 验证

`npm test` 覆盖路由、权限、旧配置兼容、身份编辑保存、部分失败、附件进度、重启与并发去重。

`scripts/verify-notification-settings.mjs` 使用隔离页面和模拟保存接口检查多渠道选择、失败保留输入、最近渠道模式、键盘关闭、375/1024 宽度、浅深色及 reduced-motion。不向真实联系人发送测试通知。
