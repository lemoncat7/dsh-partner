# 渠道通用 TTS（首版实现与后续设计）

## 2.25.0-rc.1 实现范围

独立入口位于 QQ 设置的「语音 TTS」，横线分隔。已实现 BreezeBlue、OpenAI 兼容 speech、自定义同步 HTTP（二进制 / JSON Base64），凭据库保存密钥、保存后本地试听、当前 QQ 会话交付与持久化回执。未实现其他渠道交付、下载 URL、异步任务、音色管理和输出模式选项；以下规划超出此范围的内容不代表已上线。音频内部保存目录为状态文件旁的 tts-audio，当前保留文件，不自动清除未知投递。

## 已核实的 BreezeBlue 链路

来源：伙伴工作目录 deliverables/BreezeBlue-正式TTS与QQ语音条调用-20261105.md、实际调用脚本和 artifacts 中生成回执。

- POST https://api.breeze.blue/v1/text-to-speech/{voice_id}?output_format=wav&delivery=sync
- xi-api-key 鉴权，JSON 请求体含 text、model_id=breeze-tts-2、language_code=zh。
- 可选 instructions 与 voice_settings（speed、volume、guidance_scale、use_speaker_boost）。这些字段不是所有供应商都支持。
- 同步返回音频 bytes，不能按 JSON/base64 读取。设计预览接口则是另一套响应，不能混用。
- 早期正式 ID voc_achvnu66nndy 的真实回执为 HTTP 200、audio/wav、307186 bytes、generated=true。
- 后来 B 版 voc_km2wybxwhvqm 的回执是 saved_and_verified；本次未发起该 ID 的收费 TTS，不声称已验证其合成效果。
- 原流程由模型找脚本、恢复凭据、运行合成、调用 partner_qq send_voice。现有 partner_qq_reply 则用 QQ 内建音色，二者不是一条生成路径。

## 配置模型

复用的语音服务配置：ID、名称、适配器类型、base URL、密钥引用、模型、默认音色、语言、输出格式、供应商受支持参数。密钥由后端保管，只向 UI 返回是否配置，不放入模型上下文或聊天记忆。

渠道的“聊天回复 → 语音/TTS”：允许语音回复、服务选择、默认音色覆盖、输出模式（模型按场景选择/仅用户要求），本地试听按钮。保留 QQ 原生 TTS 兼容项，已有配置不自动切换。新服务配置必须保存校验后才生效。

用户现在希望添加的是日常文字转语音；创建/克隆/删除音色另属音色管理，不混入每次回复。

## 分层

1. 供应商适配器：统一 synthesize(text, voice, options, signal)，返回验证过的内部音频产物及回执。
2. 交付适配器：当前渠道的 sendVoice/音频附件能力；能力不支持时明确使用文字，不把附件伪装成语音条。
3. 伙伴工具入口：partner_tools 中查询/调用 partner_voice_reply。仅接收 text、允许的音色与可选 continueTurn，不允许模型指定任意 URL、鉴权头、文件路径或其他收件人。

QQ 使用现有 record 消息发送路径；其他渠道逐个核对协议和媒体格式后接入。供应商格式和渠道格式分别建模，不能假定所有渠道都支持 WAV。

## 通用服务支持范围

先实现 BreezeBlue、OpenAI 兼容 speech、现有 QQ 原生。随后提供受约束 HTTP 模板：POST URL（路径变量编码）、headers 密钥引用、JSON 结构中的 text/voice/model 占位、二进制音频/JSON base64/JSON URL 返回类型及字段路径。不执行任意脚本；JSON 字段值用结构化替换，避免注入或破坏 JSON。

异步任务不是同步模板的变体：需要额外定义提交、状态查询、完成/失败判断、产物获取和恢复规则；第一版只明确支持同步，不能宣称所有 TTS 即插即用。返回下载 URL 须独立校验地址、重定向与大小，不转发服务鉴权头到其他主机。

## 执行与重试

按已保存配置合成 → 验证状态/MIME/音频内容与大小 → 保存工作目录内内部产物 → 再核对会话对象、权限、输入、配置修订 → 发送 → 持久化回执与 spokenText。

合成与发送各自记录状态；以操作 ID 区分重试和新请求。合成成功但发送失败时复用同一产物；超时无法确认服务是否受理时不盲目重新合成，供应商支持幂等或任务查询时用其恢复。发送结果未知时不自动重复发送。

语音已确认送达应计入有效回复，避免“未生成可回复”兜底、重复文字或由自主活动补任务。continueTurn 控制是否继续本轮，不一律强制结束。没有发送成功时允许简短文字说明；发送状态未知时不要谎称失败或成功。

关闭服务、撤回渠道授权或切换当前对象后，进行中的旧音频不能继续投递。取消不能被视为取消了供应商已经受理的收费请求。成功/失败日志不含密钥、完整鉴权头。

## 人格与分段

台词由当前人物正常生成，不再独立改写语气。音色和表演指令均为可编辑配置，不在插件写死具体人物。普通短句语音可合成一条；多条语音仅在明确选择分段时顺序执行，逐条记录，保留已送达部分，防止中途失败后整组重发。

## 验证边界

单元/模拟接口覆盖二进制、base64、URL、错误体冒充音频、大小与超时限制、密钥脱敏、会话切换与权限撤销、生成后发送失败、未知回执、重启恢复、已送达去重和回合完成。

真实验证先本地试听并检查音频，再在授权的测试会话验证 QQ 语音条；不能用“HTTP 200”替代音频可用或收件确认。

本文件仅为方案；本轮未修改渠道配置、调用付费 TTS 或发送新语音。
