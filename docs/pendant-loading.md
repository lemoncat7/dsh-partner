# 卡牌渐进加载

## 加载边界

- 伙伴卡牌启用后立即绘制轻量的 2D 卡面和绳子；复用 3D 卡面的绘制函数。消息数字与消息入口不等待 Three.js / Rapier。
- 当前已有未读时优先显示消息面；无未读时显示自定义图案或默认图案。图片读取失败保留默认卡面，过期的图片回调不覆盖新状态。
- 仍保留首屏避让与页面隐藏时等待机制。空闲后使用 DSH 原生 `require.async('./client.pendant.js')` 加载渲染包，沿用宿主带版本的资源缓存，Web 与 Desktop 使用同一协议。
- 渲染包保持独立，不把物理引擎放回启动包；并发加载合并，成功后复用，失败后再次启用可以重试。准备好后替换静态展示；3D 失败时仍可打开消息。
- 关闭卡牌不加载渲染包并停止消息轮询；迟到的异步结果不得在卸载后创建卡牌。隐藏页面的物理渲染暂停、静止休眠和帧率上限沿用原实现。

## 图片与兼容

- 新上传的卡片/绳子图片优先使用 WebP 有损编码（quality 0.85），超出存储上限时逐步降低品质；浏览器不支持 WebP 编码时回退 JPEG。保持长宽比与既有尺寸上限，不受显示清晰度滑块影响。
- 不自动改写用户已经保存的图片。重新上传后使用新的压缩策略。
- 保留旧 ESM 资源端点供已经打开的旧客户端使用，并补充内容 ETag / 条件 GET；新客户端使用宿主版本化分包。构建先产出分包，再产出入口，保证缓存版本更新。
