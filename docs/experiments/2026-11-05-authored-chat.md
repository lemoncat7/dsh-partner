# 聊天成稿直接投递试验

基于 2.24.0-rc.9 开发；2026-11-05 以 2.24.0-rc.10 部署生产 DSH 0.2.2-rc.1，尚未 push 或公开发布。生产人物设定未修改。

普通聊天的 `messages` 与中途接话的 `text` 已由主模型结合人物设定生成。原流程再次调用模型改写这些文字，存在合并分段、改变措辞和延迟的问题。本次将两个聊天入口标为已成稿，保留投递前状态检查与发送前再次验证，但不再调用模型改写。

`expression/workReply` 继续作为可选的只读生成路径，保留真实工具结果引用、失败信息、权限与输入变化检查。公开评论仍使用原有渲染路径。工具说明保留交付协议，删除反复指导语气与优先交接表达器的措辞；不在代码中加入角色专用词、年龄或台词。

## 实验

使用生产配置的实际模型、同一份当前角色正文和近期真实对话及工具回执，分别以原工具说明和精简说明生成首稿，再比较原投递改写结果与直接保留首稿。两轮共 14 次首稿生成，每次均运行旧改写器作为对照，无 QQ 或 B站实际发送。

这是缩减上下文的受控回放，不是完整生产请求复现：未纳入所有系统上下文和其他工具，不能据此断言主会话中的全部问题由工具说明导致。旧会话日志包含旧版 surface 元数据，因此没有修改日志或强行套用新版折叠结果来构造请求。

14 个样本中，旧改写器 13 次改写、1 次检查回退，2 次把多条文字合并。该辅助调用耗时中位数约 4.66 秒。精简工具说明没有显示稳定的人物语气增益；去掉二次改写可以确定保留首稿与原分段，并省去这次辅助调用，但不能保证首稿已经符合用户的主观语感要求。

工作回复仍存在解释过多和自报年龄等现象。此次不更改角色正文，也不宣称语气已达标。线上效果需要另行验证。

## 验证

- 构建通过。
- 新增测试：已成稿聊天不请求模型，保留文字、分段和表情顺序；输入改变后旧投递验证失败。
- 新增测试：已成稿标记不能绕过公开评论渲染。
- 更新旧测试对聊天辅助调用次数的预期，继续验证报告交付、长度限制、工作失败、表达器回退和正常结束回合。
- 最终全量 1372 项测试全部通过；测试不证明主观语气达标。


## rc.10 部署后回归与 rc.11 修复

最新用户消息“？”对应 seq 75421。模型在 seq 75425 直接输出带空行的最终文本，没有 tool/call；当时工具列表仍含 partner_chat_reply，分段设置仍为 true。这解释了该轮既无聊天工具卡、又没有分段的现象。前台普通最终文本未走闲时活动已有的短段落兜底。

rc.11 恢复明确的聊天工具投递要求，并让前台渠道最终回复在开启分段时复用短段落兜底；不添加虚构工具事件，也不把代码、列表、长文档强制拆段。补充复现测试覆盖无聊天工具的最终回复、分段关闭、四段消息及已送达去重。

用户追加的句数/标点要求归属「短句接话」与分段同时开启的组合：每段半句到两句，逗号和句号合计最多三个，允许超过三段，不以连续小段倾倒长解释。其他回复风格不套用此项生成规则。
