# 持续关注：自主维护与用户控制

- 关注执行不依赖通知渠道：使用伙伴本地会话或已批准的原渠道上下文，没有执行会话时创建本地会话记录。检查及记录同步照常进行，无投递渠道时跳过通知；静默时段和每日提醒额度只约束投递。未批准联系人的会话不作为执行上下文。
- Agent 创建和编辑均支持 `resources` 检查依据列表：`{kind: "file" | "knowledge" | "note", locator, label?}`。编辑不传保留、传列表替换、`[]` 清空；创建仍兼容文字引用。文件用工作区相对路径，知识用库名/文档名，笔记用准确 ID。
- 笔记依据可由页面候选选择，文本表示为 `@笔记[ID]`。后台通过 `heartbeat_read_note_source` 分页只读已绑定的笔记；缺失或读取失败需按检查失败处理，不降级为凭空推断。记录位置依然单独配置，关联依据不授予写权限。
- 关注工具独立于长期学习开关：有效伙伴会话始终可以新增和管理关注，普通会话不可访问。已有会话在下一次提示词组装时读取最新归属，无需重建会话。
- 持续感知开关只控制后台自动检查，不控制关注工具；手动检查仍可使用。关闭长期学习会停止逐轮记忆提炼，但不会跳过关注工具的保存通知，也不影响对话中直接调用关注工具。
- `priority` 表示伙伴投入的关注度，与观察事件的 `interruptScore`（打扰分数）分开。
- >= 0.8 重点关注，>= 0.4 持续跟进，其余暂时观察。隐式关注经有理由的调整降到 0.18 以下时归档。
- 不因没有消息、时间流逝或心跳执行次数机械降分。沿用已有周期回顾和逐轮记忆提炼评估，不增加独立模型调用或每条定时任务。
- 显式关注不因低分自动归档；管理工具需说明已解决或到期的结论。模型的事实判断仍需具体依据，不能用“没提及”替代核验。
- `partner_concerns` 无需新的语义授权即可更新内容、关注度、解决、归档、恢复；仍按当前伙伴隔离，使用 `expectedUpdatedAt` 防止覆盖。
- `reason` 是本次调整原因；`details` 才替换原有关注说明，单纯调分不会覆盖执行说明。
- 用户置顶 `pinned` 禁止伙伴降温和结束；用户停止 `stopped` 禁止伙伴恢复或通过同主题 upsert 重建。页面“继续留意／取消置顶”交还自主维护权。
- 删除不再暴露给 Agent，页面确认后才永久删除。同主题候选继续合并更新，复用原条目；不做模糊匹配批量合并。
- 每条保存最近 20 条调整记录。归档可恢复；恢复保留原 id 与历史。旧归档原因不可区分，迁移时保守保护为 stopped，用户可手动恢复。
- 在途检查读取最新版本，已编辑／停止／归档的条目不会被旧结果复活。归档／解决条目的待提醒不会继续发送。

验证：665 项测试通过；隔离浏览器 fixture 验证阶段、记录、置顶、归档恢复，以及 375 / 1280 宽度和明暗主题布局。fixture 仅替换宿主装饰图标。
