# 后台读写与任务生命周期

渠道「通用」中的 TTS 与浏览器设置作为小型组件随主入口加载，不再在打开设置时请求带旧 revision 的延迟分块。已有旧入口仍保留历史分块产物；部署验证必须实际打开两种设置，且在模拟相应分块 404 时均能使用。运行 `npm run test:channels-browser`，可通过 `DSH_PLAYWRIGHT_MODULE`、`DSH_CHROMIUM_EXECUTABLE`、`DSH_BROWSER_URL`、`DSH_BROWSER_COOKIES` 指定本地浏览器与私密登录 cookie 文件。该检查只打开、读取和关闭配置，不保存配置、合成语音或连接 CDP。

原生 Jobs 与子 agent 分别使用：单条长命令、下载、转码、构建或测试可在原会话用 `bash` / `terminal_send` 的 `run_in_background:true` 启动，再由 `job_list` / `job_output` / `job_kill` 管理；独立推理与多步工作仍通过 `partner_background_task` 委派原生子 agent。原生任务状态计入伙伴忙碌状态，agent 空闲不代表其命令已结束。

原生 Job 注册时，伙伴只保存原输入与渠道归属的业务记录，不接管执行、输出游标或原生任务目录。原生完成通知沿该记录交付；新用户输入与不同来源的完成通知分到原生不同回合，保留消息 ID 与内容，避免共享会话串人。渠道、账号、投递地址或授权发生变化时保留原生输出，不转投新对象。

模型响应在执行工具之前因工具参数 JSON 无效而返回 `MALFORMED_RESPONSE` 时，在原生 `agent/request-error` 回调内对同一步最多重试两次；格式纠正提示写入原会话并进入重试请求，原用户回合与已成功的工具回执不重放。取消、新用户 steer、普通工具错误、有效 JSON 的参数校验错误及无关模型错误交还原流程；两次仍失败则保留失败状态。

伙伴后台工作通过公开的 `ctx.subagents.registerProvider` / `startActivation` 创建，原生运行时负责子会话、目录、继承权限、状态与资源释放。插件不再直接创建 Agent，也不写入 `subagent/descriptor` 或 `subagent/catalog`。首次执行以 `delivery: caller` 接回原生结果；暂停/取消释放原生 activation，恢复同一原生子会话使用公开 `sendMessage`，补充与释放也走原生接口。

冷恢复接口只返回消息回执，且不会恢复上次的 outputSchema。伙伴因此只在自己的恢复窗口注册交付清单工具，通过公开 `subagent/start` / `subagent/end` 接回本轮结果；只有成功的最终工具回执（嵌套执行还须外层成功）才算交付。原生恢复自动产生的完成通知在原会话的 pre-step 中消费，由伙伴沿冻结的发起人/渠道统一交付；混合批次中的真实用户输入及其他插件通知保留。原生 UI 不得绕过伙伴任务入口直接恢复该子会话，避免丢失任务授权和交付归属。

旧版直接创建的子会话没有可恢复的原生身份。首次继续时，只读取得完整历史，经原生 provider 的 seed 能力创建一个带历史的新子会话，业务 taskId、工作目录和已有产物保持不变，旧 childId 保存在 previousSessionIds，旧日志不改写、不删除。原生工厂拒绝损坏/不完整的 seed 时明确报错，不退回重做原始任务。新原生任务的后续恢复保留 childId，不重复登记。

同一来源、同一 BV 视频的下载／提取任务尚在运行时，即使新请求换了标题或改写要求，也会补充到原任务。分析、剪辑、不同视频和明确要求另开独立任务继续分别处理；已有范围与权限检查仍生效。

记忆 worker 保持全局单路处理。有待处理记忆时使用 5 秒间隔，连续空闲后逐步放缓到 30 秒，减少重复打开记忆和画像数据库。正常对话完成归档后直接唤醒 worker，约 1 秒后检查；处理期间的新唤醒合并到下一轮，不并发提炼。手动补录和跨进程产生的工作仍会在后续检查中发现。原始聊天和真实提炼结果继续可靠保存。

疲惫值由时间和已有睡眠记录即时计算，不因每分钟检查而刷新存储时间戳；入睡概率为零时也不保存无效抽签。睡眠、唤醒、用户输入仍保存真实变化。睡眠或角色开关切换在统一状态提交时保存一次检查点，关闭期间不继续累计，恢复后也不将停用时间补算进去。这避免了睡眠疲惫已经为零时，仍每分钟重写整份状态文件。

滚动对话窗口使用当前 surface 中的节点构建临时索引，避免每步为全部历史建立多个 Map。相同会话事件版本和窗口设置下，系统段组装与 pre-step 共用本次处理结果；新事件或设置变化会重新计算。原始事件图仍由宿主持有，此优化不删除历史，也不承诺整个历史图已经卸载。

每日上下文焕新按生效策略判断滚动窗口是否开启。关闭角色聊天后，保存的滚动选项继续保留；运行时窗口暂停时，不会因此误停仍开启的每日焕新。

周期调度先在串行写入中认领到期机会并推进下一次，再派发执行。同一到期机会不会因 15 秒轮询再次加入队列；只有下一周期真正到期且旧工作尚未结束时，才按 queue/skip 处理。执行完成只保存结果，不重复推进周期，也不覆盖执行期间用户修改的下次时间。手动触发保留计划时间。

关闭时停止新认领、取消执行信号、清除进程内待重跑标记，并等待周期任务、续接执行和通知收尾；关闭返回后不再派发新执行。进程异常退出时，外部操作仍需结合保存的执行记录核实，不保证外部副作用严格只发生一次。

共享会话中的关注保存与回合结束处理共用消息来源解析。优先使用登记的消息编号和持久来源记录；本地输入归本地路由，渠道输入归原渠道。不会按路由数组先后决定范围，也不会把已移除来源自动当成本地用户。
