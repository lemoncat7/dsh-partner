# QQ 群聊接话：会话归属、时间与本地语义（本地多场景识别）

本地分类用于快速分流，不生成回复，也不授予任何工具权限。单句被分为“交流”不代表它在向伙伴说话。

## 路由顺序

1. 明确停止接话先结束当前成员的接话状态。真实 @ 伙伴、引用伙伴已确认发送的消息、直接叫当前角色名仍优先进入回复流程；其他称呼由本地语义识别，不维护写死的关系称呼表。
2. 真实 @ 他人、引用其他成员的消息旁听；单独的确认收尾语和没有当前对话对象的孤立标点也可直接旁听。
3. 同一群、同一发言人刚收到伙伴回复，30 秒内没有新的其他成员插话时，连续补充直接进入原对话，不重复等待分类。其他人插话不删除此人的对话状态，但恢复语义判断。只有成功送达建立连续性；发送失败、仅入队和旁听不延长窗口。
4. 面向全群的明确询问或交流邀请可以直接进入接话判断。群友互聊中识别到一般接话机会时按 65% 选择进入，其他机会继续旁听；这是可选准入，不是强制回复。
5. 正向分类 confidence >= 0.65 / margin >= 0.15，或 confidence >= 0.58 / margin >= 0.20，可进入判断。较弱的正向结果（>= 0.48 / 0.12）结合背景关联分数 >= 0.40，也可进入判断。不确定的 close/background 仅在与近期话题高度相关（>= 0.60）时交给主对话判断；明确否定（>= 0.72 / 0.35）、显式转向他人和收尾语仍旁听。这些数值不是准确率。
6. 伙伴实际回复本群后三分钟内，其他成员与近期话题关联 >=0.45 的补充可按共同续聊进入，不重复抽取概率或等待插话间隔；明确转向他人、收尾及强负向分类保留。只有真实送达延长窗口，旁听与准入不延长；不同群、渠道和输入之后的发送记录不会被误用。
7. 同群非定向主动插话最短间隔 5 秒，明确呼唤与已建立的同人对话不受此限制；正在执行任务或本轮已有消息送达时，普通群聊仍按任务/回复窗口保护旁听。

识别服务 v3 接收最近 90 秒内最多四条背景，每条最多 48 字符，优先保留最近成员消息和伙伴上一条已确认送达回复。当前句独立做意图分类，冻结句向量只计算与背景的关联，不把历史呼唤当成当前指令。短期缓存仅保存文本摘要键和向量，最多 128 项、两分钟过期，不写入磁盘或长期记忆。旧服务仍兼容单句分类，只是不返回背景关联分数。

主模型会收到群内近期实际参与状态，结合自己的上一句话自然承接其他成员的新补充，不因换发言人退出共同话题。

进入回复流程不保证必回，自主白名单群中仍允许 `partner_chat_reply messages:[]` 安静结束。私聊与浏览器不能借此空回复。

## 多场景识别与选择

在保留原意图头的基础上，增加同一冻结编码器上的八类场景头：呼唤、求助/观点交流、接梗/吐槽、分享见闻/情绪、提出话题、确认收尾、明确指向别人、背景消息。场景头用 286 条公开编写的通用样本训练，独立编写的 40 条场景测试中 36 条分类正确，27 条达到场景准入阈值且这 27 条分类正确；验证见 `ops/attention/scene-evaluation-report.json`；这些指标不代表真实群聊准确率。

场景证据要求 confidence >= 0.60 / margin >= 0.20，或 >= 0.50 / 0.25。呼唤原意图另允许 confidence >= 0.45 且 margin >= 0.25，修复短呼唤领先差清楚但绝对分值偏低时被漏掉的问题。较明确的非呼唤场景不能借原意图里的 address 走呼唤捷径。明确 @、引用、停止、转向他人的渠道事实仍优先。

场景头理解当前句；上下文选择策略结合实际送达的上句话、参与时间、群友是否正在互聊和当前伙伴设定相关度。画像取当前名称与身份描述，关系文本只对渠道核验的绑定发言人提供，最多三段、每段 160 字；伙伴最近已送达正文另限 160 字。画像相似度不是身份依据，也不授予权限。和近期普通群消息相似不代表伙伴已参与该话题。

已参与/与已送达回复相关的场景可续聊；新的求助/话题机会按 75% 选择，分享/吐槽与人物相关时 65%，其他成员正在互聊且无相关依据时 25%，其余 50%。仍受同群 5 秒主动接话间隔约束；真实呼唤不抽签。数值是准入选择率，进入生成后仍可安静结束。忙任务时只允许呼唤，普通机会不排队补答。

识别出的场景及分值进入诊断记录，当前消息的可靠场景线索交给回复环节，按当前人格决定接梗、认真回应、分享或沉默，不强制挖苦。没有新消息时，主动抛话题仍由已有闲时自主活动调度，结合最近场景和自身兴趣决定，不用每条群消息额外启动一次闲时活动。

## 连续消息与时间

同人同引用目标的消息跨 poll 合并，等待 600ms 安静窗口，最多 2400ms/16 条。已进入回复后，同人的后续补充通过原有 steer 机制接续；不同人、群与引用不合并。识别延迟、合并等待、主模型生成和发送耗时是不同环节。

临时群背景最多 16 条，含真实渠道时间、相隔秒数及已确认送达的伙伴回复；十分钟前的临时背景不再注入。会话时间提示细化到秒，区分快速补充和明显间隔。时间缺失或未来时间不伪造，不删除持久会话历史，不将群旁听写入长期记忆。

独占人物提示模式仍保留已开启的消息分段配置，允许一轮多条或中间继续说话；不规定最低消息数、不硬编码人物口吻。

## 排查数据

`/partner-local/v1/channels/status` 的 QQ 渠道带 `groupDecision` 和 `groupDecisions`。后者只保留当前进程最近 40 条时间、消息标识、路由、耗时和可用的分类分值；不含消息正文，不持久化。`qqLatency` 仍区分识别与主模型等耗时。重启后为空，不能用它推断重启前全量识别准确率。

## 模型与验证范围

采用冻结的 `Xenova/paraphrase-multilingual-MiniLM-L12-v2` INT8 ONNX 编码器，加本地训练的 L2 正则化 softmax 分类头。不是完整 SetFit 微调，也没有直接套用论文训练模型。分类头用仓库中 training.json 的通用中英文及少量日文样本训练，不将用户私有聊天上传或写入训练集。

独立编写的 40 条测试样例包含最近漏回的短句，最初分类头的分类准确率 90%；23 条呼唤/交流样例在这一小样本内全部归入正向类别。不能据此承诺真实群聊零漏判。完整结果（包括错误）见 `ops/attention/evaluation-report.json`；测试集不参与训练。另有路由测试验证换人、过期、不同群、发送失败、引用真实性、故障放行与权限边界。

最初部署时的离线测试：单条平均约 6.4 ms、P95 约 8.8 ms，进程峰值 RSS 约 541 MiB；容器实测可能不同。模型 118,308,126 字节、分词器 17,082,913 字节。服务只处理短文本，不生成回复、不执行 QQ 操作、不持久化聊天；运行中无需联网下载。正式回复仍使用原模型，不能据此保证总回复时间低于 5 秒。

## 部署

`ops/attention/` 提供 Dockerfile、compose、固定模型修订与 SHA256、训练及验证脚本。权重不塞入 npm 插件包。

```sh
cd ops/attention
python3 download-model.py
docker compose up -d --build
```

Compose 使用外部 `appnet`，不映射宿主机端口；限制 1 CPU、768 MiB 内存、禁止额外 swap，非 root、只读运行。宿主机设置 `DSH_PARTNER_ATTENTION_URL=http://partner-attention:8092`，或在 `$DSH_HOME/partner/local-attention.json` 写入：

```json
{"url":"http://partner-attention:8092"}
```

重新加载伙伴插件后读取配置。未配置时仅使用会话路由；没有明确呼唤或现存对话依据的新消息旁听。客户端共享 1500ms 总预算；仅连接中断最多重试一次，超时不重试；故障退避 1～8 秒，不重复堆积推理。单进程最多四个分类请求在途，繁忙时同样使用会话规则，不能无限排队。通过 `/health` 检查就绪。停用时先移除配置并重载插件，再停止分类服务。

源码与样本修改后，可安装 requirements.txt，运行 train.py、evaluate.py 重新生成分类头和报告。场景头用 `train.py --model-dir model --training scene-training.json --output scene-head.json` 训练，再用 `evaluate.py --model-dir model --head head.json --scenes` 验证。不得把测试样例添加进训练集后继续宣称原测试集准确率。

## 提及其他成员时的对象识别

保留 OneBot 结构化 @ 在正文中的位置，不把昵称或 QQ 号写入识别文本。开头直接 @ 其他成员仍旁听；正文中途的 @ 可能是在谈论某人，交给本地模型识别，输入用 `@其他成员` 标记原位置。例如“搭档，你觉得 @某人 他打球怎么样”与“小王，你觉得 @某人 他打球怎么样”不能仅靠出现了 @ 来作相同处理。

这类消息须有呼唤伙伴的语义证据才放行，近期聊过、疑问句或话题相似均不能单独放行。识别通过时保留对话连续性；确认转向其他人时关闭该成员的续聊线程。忙碌期间复用同一识别结果，不增加第二次模型调用。称呼只出现在学习样本中，路由代码没有关系称呼列表。

`recipient-evaluation.json` 是另行编写且不与训练集重复的对象识别检查样本；通过 `evaluate.py --model-dir model --head head.json --recipients` 检查。分类头排名和场景头排名均不是校准后的概率，仍可能漏判；检查时应同时关注反例及最终路由，不只看整体准确率。
