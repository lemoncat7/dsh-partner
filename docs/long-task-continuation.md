# 长任务一次性续接

## 看板等待协调

看板执行内的 `defer` 支持 `boardTaskId`，服务端还会按正在执行的委派及实际会话自动匹配唯一任务。
预约持久化时将该委派挂起，任务保留进行中，但调度信息显示“等待外部任务结果”和下次检查时间；不占用看板执行位、不触发恢复重试、不进入验收，也不触发需求阶段完成通知。

关联看板的唤醒只检查外部状态：pending 延期原预约，completed 唤醒原委派继续 nextStep，而不是定时会话再做一次 nextStep；真实交付仍须通过原看板验收流程。取消、删除、检查失败、权限撤回将任务置为受阻，不自动重新提交外部任务；暂停预约保留等待。修改工作版本、改派、删除任务会使旧预约及迟到回执失效。

绑定信息及工作版本随原状态持久化，重启不会把等待委派当作新工作派发。续接结果通知统一归需求处理，不逐条通知定时检查。普通未关联看板的续接保持原有行为。旧的一次性预约可以在同一会话、同一外部 ID、同一 taskKey 再次 defer 时安全关联当前执行任务；无法确认归属的旧周期计划不会按标题或文本猜测并自动迁移。

职责：`tasks/continuation` 维护绑定和跨域事务约束，`tasks/continuation-yield` 释放会话执行等待，调度服务只推进预约状态，看板继续持有交付和验收的责任。状态存储在持久化前统一检查约束，避免删除或编辑入口遗漏导致失效预约继续运行。

## 能力与技能

伙伴必须启用 `schedules`（定时任务）能力。工具注册、每次执行、服务层创建和调度执行均校验；停用后不会唤醒或发送后续通知。已运行的续接请求中断，外部已提交任务不会自动撤销。

内置市场提供可选的“长任务等待与续接”inline 技能。需要时安装并绑定，不自动启用。基础参数协议直接在工具和能力提示中提供，未启用 skills 或未绑定技能不影响基础调用。

## 工具协议

复用 `partner_schedule`：

- `defer`：必须传 `taskKey / externalTaskId / title / check / nextStep`，当前正式伙伴会话由服务端确认。可传 `delayMinutes`（1–1440，默认2）、`deadlineMinutes`（不早于首次预约，最多43200，默认1440）、`maxAttempts`（1–100，默认12）。同伙伴同 taskKey 幂等，终态不重置预算。
- `resolve`：当前唤醒轮次传 `scheduleId / runToken / outcome / summary`；`pending` 保存原条目延期，`completed` / `blocked` 停止执行。检查完成不等于外部任务完成。
- `cancel / delete`：停止续接，中断正在执行的轮次；不代表已取消外部任务。
- `list`：查看自己的计划、检查次数、截止时间及最近结果。已有 update 支持暂停等待中的续接，不能改成周期或绕过终态重新执行。

## 架构

- `scheduler/service` 保持统一入口和已有周期调度。
- `scheduler/continuations` 负责持久化续接状态、幂等、预算、轮次 token、撤权取消、执行记录和终态通知重试。
- `PartnerAgentRuntime.wakeSchedule` 复用原会话的工具与审批；空闲时 followup，运行时 steer 到下一处理点。`scheduler/wakeup` 只等待本计划持久化回执，不等待会话 idle 或 Goal 完成。超时暂停预约但不取消共享会话；原会话删除/归档不换会话。
- `ChannelManager.notifyContinuation` 复用现有通知目标选择与分片收据。等待不通知，完成/受阻才通知；本地无通知目标时保留会话和计划记录。
- 内置技能只提供策略，不获得权限，不把所有工具加入白名单。

数据复用已有 `schedules` 和 `executionRuns` 持久化/分区存储，不创建散落文件、不更改旧数据布局。新增 `schedule.kind=once` 和可选 continuation 字段；正常周期计划不转换。

## 恢复与安全边界

恢复时在 system-prompt/assemble 检查伙伴装配版本，若本次新装配则重建这次快照，让首次请求就携带身份与工具；不能只在 agent/pre-step 注册，因为当前宿主在该事件前已经采集了工具。并发装配合并等待，失败阻止模型请求，重建保留宿主的工具过滤与权限。唤醒投递前检查最终可见的 partner_schedule 与 check 明确命名的 MCP 工具，缺失时记录受阻，不发出缺工具的唤醒。旧预约未填 completion 时只核实当前外部任务成功，不把旧 check 的整条后续流程当作完成条件。

等待中的计划重启后仍按时间执行；运行中断的计划以新 token 重新进入核验，先查询已有任务/已有产出，禁止再次提交。外部副作用无法在通用适配器层保证 exactly-once，技能明确要求幂等检查；执行异常或未提交 resolve 默认受阻，而非无条件自动重跑后续步骤。

检查采用原会话和工具审批，不能绕过未授权的 SSH/MCP/文件操作。计划字段不应写凭据或签名下载地址，只保存引用。相同伙伴同时投递一个续接，收到该预约结果即释放，不被整个对话阻塞。

可选 completion 明确本预约的完成条件（默认仅核实本外部任务成功且产出可回查，不复用旧 check 中混入的后续动作）；一旦核实先 resolve completed，再做 nextStep。后续新长任务单独预约，与 Goal 无依赖。原会话可携带精确 externalTaskId 提前关闭 waiting 预约，不传 token；running 状态必须使用当前 token。pending 保存延期。timeoutMinutes 默认 10（1–120），超过后暂停并保留原因。过期唤醒在执行前必须 list 核对 token；不保证撤销已提交的外部副作用。

首次实现不解析任意用户文本自动撤销外部服务任务；伙伴收到用户取消指令应调用 cancel，管理台可直接删除预约。截止/次数是持久预算，不因重复 defer 或重启重置。

验证覆盖能力开关、幂等、迟到 token、取消/撤权、期限/次数、重启恢复、可选技能与通知抑制；浏览器用隔离 API fixture，不向用户渠道发送测试消息。
