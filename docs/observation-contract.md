# 通用后台观察契约

## 认证与未完成检查续跑

从关注说明和执行要求中的明确“凭据仅用于某域名”声明提取认证域名约束；不根据所有链接猜测授权。对这些域名的 `web_fetch` / `web_source` 直接请求会被阻止，模型应使用原会话已授权的命令能力加载指定凭据。此机制不新增命令权限，也不替换命令工具自身的审批；它不能证明任意自定义脚本实际发送了正确认证。401/403/429 返回后提供区别诊断要求，403 本身不是限流证据，禁止盲目重复匿名请求。

检查期间每次工具返回后，自动保存有限的脱敏结果摘要（不保存调用参数），受阻时保存未完成原因；与对用户记录笔记的同步完全分离。下轮可续查，24 小时后或关注依据配置改变后不复用；旧摘要只是事实材料，不是新指令，也不代表核验成功。截断部分与时效性事实仍需重读。成功检查清除续跑摘要，配置并发变更拒绝写入旧进度。

检查保持12轮加一轮无工具收尾，最后三轮提前提醒收敛到一个具体候选。单候选满足条件可交接执行，不要求其他候选也全部完成；不足条件仍返回受阻，不降低证据门槛。

后台观察不包含任何站点或发布平台专用逻辑。检查阶段从来源会话继承工具清单，不再通过固定白名单排除已授权的插件能力（包括 SSH）。实际调用仍走原生工具执行管线、父级权限及工具自身授权检查；可见性不是新增操作授权。模型只执行关注明确要求且已授权的操作。记录同步阶段仍限制为指定记录目标，检查阶段不能直接改写记录文件。模型在读取检查依据后先核对必要能力，缺少能力时报告具体步骤，不得借其他工具绕过权限。

结果分类：`changed`（新增）、`unchanged`（无变化）、`already_processed`（已处理）、`baseline_initialized`（首次基线）、`blocked`（核验未完成）。来源变化与执行资格分离：`executionNeeded=true` 必须附稳定 `executionKey`、具体事项及核验证据，并且关注已配置执行要求。首次基线和无变化也可能含未处理事项；已处理或核验受阻不能标成待执行。检查阶段接收执行要求，但不直接完成重型交付。记录、观察或通知不等于交付完成。

执行键由来源对象、目标动作和必要版本构成，不含本轮时间或变化的摘要；持久化回执防止重查及重启重复执行。首次基线待办只进入动态与执行队列，不伪装为新增提醒。失败回执不盲目重放。显式 `executionNeeded=false` 的观察不触发执行；旧版缺省字段兼容原流程。

失败分类：能力缺失、认证、限流、网络、证据不完整、未知。限流恢复时间由实际响应提供为 ISO `retryAt`；仅 HTTP 403 不能断言限流。调度同时更新关注条目和伙伴唤醒时间，报告计划复查时间，实际执行仍受静默时段及服务状态影响。

其他插件可通过 `partnerObservationSources` 服务实现 `ObservationSourceRegistry.readTools`，返回 `observation_read_*` 只读适配工具。适配器必须自行核验伙伴/关注资源范围、凭据所属来源、分页及超时，并禁止任何写入。该服务是宿主代码显式接入点，不接受模型注册、不根据工具名字或并发安全标记自动授权，也不直接开放 SSH。

适配器是可选扩展，不是复用原会话已授权工具的前置条件。没有任何已授权访问途径的来源才报告能力缺失。说明内容及明文保存方式不变。
