# 跨轮生产台账

多镜头或长任务时，在用户项目内现有制作文档或一个 note 节点保留简短台账。不要为了单图任务制造复杂文档体系。可用标题“制作台账”，随本次操作更新，不能只靠聊天记忆。

## 最小记录

- 项目 ID、brief、授权范围与预算；认可的人物/场景版本。
- 创作编号（C01/L01/S01）、对应节点 ID、用途、当前状态。
- 每个生成意图的 requestId、完整提交参数、按顺序的参考资产 ID/稳定 URL、返回 jobId、resultNodeId。
- 检查时间、任务状态、canvasSync；验收是否完成、偏差与下一动作。
- 最终资产 ID、本地已验证路径、附件 deliveryId 与渠道回执（如有）。不记录令牌、签名下载 URL 或上游凭据。

例如一条镜头记录的语义是：“S03 使用 C01-v2 与 L01-v1；输入顺序人物、场景；分镜静帧已核验；视频任务仍 running；下一步只查询已保存 jobId”。节点 ID、资产 ID、任务 ID 必须来自工具回执，不能用这类语义编号替代。

## 可观察的完成条件

| 阶段 | 达成条件 | 不足以视为完成 |
| --- | --- | --- |
| 人物/场景 | 真实图像可读取、基准版本已核验 | 仅写了设定文本 |
| 分镜静帧 | 参考关系正确，人物与空间连续 | 仅连接了 image 卡片 |
| 视频生成 | 已有 jobId 且终态 succeeded，结果可读取 | submit 返回 accepted |
| 画布回填 | generation_get/sync 返回同步成功，节点关联正确 | 网页上暂时出现进度 |
| 用户交付 | 按范围交付结果；渠道附件以发送回执为准 | Markdown 中贴了路径 |

恢复时先读台账，再读当前画布和任务状态；事实冲突以服务实际状态为准，并更新台账。已认可资产不因新尝试失败被抹掉。用户改需求后只重规划受影响镜头，先检查已有任务是否已接受，不承诺当前 MCP 可以取消它。
